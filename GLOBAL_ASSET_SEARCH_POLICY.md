# Политика глобального поиска игровых ресурсов — ВСЕ форматы, ВСЕ стили, ВСЕ жанры

**Утверждённая постановка задачи: 2026-10-09.** Этот документ — первоочередное правило для любого исследовательского цикла C001+, последующих очередей моделей, материалов и агентских автоматизаций. Если старые файлы пишут «искать до 2–3 и завершить», применять это правило вместо старого.

## 1. Цена, лицензии и происхождение: жёсткий фильтр
- **Только 100% бесплатное использование в коммерческих играх** (стоимость приобретения, обязательного скачивания, экспорта и необходимых инструментов = 0 ₽). Нет обязательной подписки, платной карты/платного API, пробного периода с переходом в оплату, платной версии, без которой нельзя использовать ассет.
- CC0 приоритет, CC BY разрешено с полной атрибуцией, CC BY-SA — `LEGAL_REVIEW` и отдельная проверка ShareAlike. Иные лицензии допускаются **только после** проверки коммерческих прав и ограничений по публикации/передаче. Запретить personal-only, NC, сомнительные репаки, украденные модели, чужие бренды/персонажей без прав.
- **Любые сайты, авторы, репозитории и каталоги**, если конкретный ресурс доступен бесплатно и законно. `Catalog/SOURCE_PORTALS.md` — полезные отправные точки, **НЕ белый список** и не ограничение географии, языка, платформы или площадки.
- В публичном GitHub хранить подробные карточки, ссылки, лицензии, метаданные и свои скрипты, а не чужие большие ассеты, ZIP, текстуры или коммерчески ограниченные исходники.

## 2. Количество: 2–3 — МИНИМУМ, максимума НЕТ
- На **каждый тип объекта/текстуры/ресурса** стремиться получить **минимум 2–3 независимых подходящих варианта**, если они доступны на законных бесплатных условиях.
- **Никакого верхнего ограничения.** Найдено 5, 30, 100, 1000 качественных законных вариантов — сохранять ВСЕ различные полезные варианты, не останавливаться после третьего.
- Поиск **не считается исчерпанным** при достижении минимума: расширять источники, подкатегории, стили, форматы и жанры, периодически возвращаться к старым категориям за новыми ресурсами.
- Для категории без 2–3 подтверждённых вариантов — `BELOW_MINIMUM` и открытая поисковая задача; для категории с 3+ вариантами — `MINIMUM_MET_SEARCH_CONTINUES`, **не** `DONE_FOREVER`.
- Не считать зеркала, разную упаковку, повторный экспорт или один и тот же mesh в разных источниках за **независимые** модели; сохранять повторные ссылки и версии как связанные записи для удобства, но не увеличивать число независимых моделей без оснований.
- Считать конкретную модель/вариант в наборе только после документального подтверждения состава. Теги, общая страница категории или смежный предмет ≠ точная найденная модель.

## 3. Модальности — искать ВСЁ
- **3D:** meshes, персонажи, props, сканы, архитектура, транспорт, животные, растения, voxel/block, kitbash, modular environments, rigs, skin, mocap, анимации, LOD, collision, CAD/point-cloud с адаптацией, geometry nodes, VDB/volumetric resources.
- **2.5D:** изометрические/диагональные виды, псевдо-3D, billboard/impostor, sprite-based 3D, pre-rendered multi-angle sprites (4/8/16/32 directions), 2D персонажи в 3D-среде, tilesets, parallax and layered world.
- **2D:** спрайты, sprite sheets, тайлы, анимации по кадрам, pixel art, vector/SVG, UI, иконки, фоны, карты высот, визуальные эффекты, foliage atlases, персонажи/предметы/окружение в 2D.
- **Другие форматы, если полезны:** процедурные материалы, shaders/graphs, decals, particle/VFX systems, 3D/2D-анимации, HDRI/skyboxes, lighting, fonts (с проверкой лицензии), Blender/Unity reusable visual templates.
- Модальности не ограничиваются этим списком. Для каждого файла сохранять `representation`, `format`, `use_case`, `target_engine`, `conversion_required`.

## 4. Полный охват объектов И ТЕКСТУР
- **Весь мир предметов:** герои, NPC, существа, боссы, оружие, броня, транспорт, здания, мебель, инструменты, мир, техника, еда, мусор, декорации, промышленность, медицина, природа, растительность, эффекты, интерфейсы и любые новые подкатегории.
- **Все типы поверхностей/материалов/текстур:** кора, листья, травинки, ветки, деревья, древесина, плитка, кирпич, бетон, металл, ржавчина, шерсть животных/плюш/волосы, кожа, ткань, грязь, почва, глина, песок, гравий, снег, лёд, вода, туман, облака, дым, огонь, земля, скалы, мох, асфальт, крыши, пластик, стекло, следы, трещины, декали, карты высот, нормали, HDRI, небо, sci-fi/fantasy stylized.
- Текстуры ищем для **3D / 2.5D / 2D**, в том числе PBR tileable, atlas/trim sheets, 2D clouds/foliage sprites, volume textures, animated textures, height/noise/masks, hand-painted, pixel-art, procedural.
- **Важная разница:** PBR «шерсть/мех» не равна настоящим волоскам/геометрии. Foliage PNG не равен 3D-дереву; clouds/skybox ≠ 3D volumetric clouds — фиксировать отдельные типы.
- Не ограничиваться текущими 18 группами материалов: таксономия расширяется, а не отбрасывает новые находки.

## 5. ВСЕ стили и ВСЕ игровые жанры
- Реализм, фотореализм, hand-painted, stylized, cartoon, anime-inspired, pixel art, low/high poly, voxel, retro, PS1/PS2/N64, cel-shaded, watercolor, claymation, flat, isometric, pre-rendered, sci-fi, исторический, постапокалиптический, fantasy и другие без ограничения.
- Для любой игры: RPG, survival, strategy, tower defense, shooter, platformer, sim, city-building, racing, sports, sandbox, horror, casual, education, mobile, VR/AR, narrative, web/HTML5 и будущие жанры. Новые жанры не требуют предварительного одобрения.
- Помечать техническую применимость к платформам, но **не выкидывать** ресурс только потому, что он сейчас не нужен для текущей игры.

## 6. Обязательные поля при внесении нового конкретного ресурса
`resource_id`, `category`, `subcategory`, `representation`, `style`, `genres`, `source_url`, `author`, `license`, `license_url`, `commercial_allowed`, `attribution`, `free_download_url` (если известен), `files_and_formats`, `source_page_verified`, `exact_item_evidence`, `pack_contents_count` (если проверено), `exact_variant_count`, `license_review`, `found_on`, `duplicate_of`, `download_tested`, `blender_tested`, `unity_tested`.

**НОВОЕ обязательное поле для оценки места на диске:** `download_size_bytes` (реальное число из официального CDN/HTTP Content-Length/download manifest, если доступно), `size_source` (официальная страница/API/HEAD/архив), `size_verified_on`, `size_status` (`MEASURED`/`PUBLISHER_STATED`/`UNKNOWN`). Для нескольких форматов и разрешений — отдельный список `download_variants[]` с `resolution`, `format`, `bytes`, `free`. Не записывать придуманное число как размер источника.

**Размер пака ≠ размер отдельной модели.** Для оценки полной загрузки считать уникальные файлы в выбранных бесплатных вариантах, убирать дубли и явно указывать, какие варианты/разрешения учитываются; суммирование всех возможных форматов противоречит «скачать по одной пригодной версии».

## 7. Workflow
1. Проверить [основной индекс](Catalog/MASTER_SEARCH_INDEX.json), [материалы](Materials/INDEX.json), предыдущую очередь и лицензии.
2. Обходить **различные** официальные и общественные источники, менять языки/синонимы и форматы. Поиск не ограничен портальным списком.
3. Сохранять каждую новую уникальную подтверждённую страницу в отдельной записи GitHub, коммитами и с указанием варианта/качества совпадения.
4. Параллельно отслеживать целевое количество **2–3 минимум**, затем продолжать искать новые варианты без потолка.
5. Вести счёт реальных подтверждённых размеров скачивания и числа предметов в паках (если информация доступна); неизвестное оставлять `null`, **не приписывать 0 байт**.
6. По возможности фактически загрузить бесплатную редакцию **без расходов**, проверить лицензию, геометрию/карты, размеры, Blender/Unity, производительность.
7. После каждого прохода обновить `PROGRESS.md`, все индексы, статистику/пробелы; не оставлять новую категорию без поиска лишь потому, что текущая игра её не использует.

**Это правило действует и для любых автоматических ежечасных запусков.**
